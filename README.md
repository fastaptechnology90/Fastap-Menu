## ⛔ Commands that touch LIVE — never run these

These do **not** run by themselves. They only run if typed. But one of them is enough to change or break production.

```bash
# Deployment — pushes code to the live VPS
pnpm deploy              pnpm deploy:vps          pnpm package:vps
pnpm setup:vps           pnpm setup:ssl           pnpm pm2:start

# Restarts the live API — the whole platform goes down for a moment
pnpm pm2:restart         pnpm pm2:stop

# These SSH into the live server and run commands there
node scripts/vps-*.mjs
bash scripts/vps_full_deploy.sh
bash deploy/*.sh
```

### Why rule #4 exists (the actual reason)

`kitchenapp/lib/core/config/api_config.dart` line 36:

```dart
static const defaultExternalBaseUrl = 'https://digitalrestuarants.thefingo.com';
```

If you run plain `flutter run` with no `--dart-define`, the app falls back to this
and connects **straight to the live production server**. Real orders. Real data.

`pnpm dev:kitchenapp` passes `--dart-define=API_BASE_URL=http://127.0.0.1:8080`,
so it stays on your laptop. Same for `dev:waiterapp` and `dev:housekeepingapp`.

## ⚠️ The VPS is SHARED — 18 projects live on it

`82.25.108.80` also runs other clients' projects:
`egymedics` · `king-vpn` · `lamyarstv` · `parklink` · `echosphere` · `saajbymf` · and more.

| Never | Why |
|---|---|
| `pm2 restart all` / `pm2 stop all` | Takes down **18 clients** at once. Always name the app: `pm2 restart fastap-api` |
| `pm2 delete <anything>` | Removes it from PM2 — it won't come back after reboot |
| Server **Reboot** in hPanel | Every site down for ~2 minutes |
| **Reinstall / Rebuild OS** in hPanel | Wipes everything. No undo. |
| **Reset root password** in hPanel | Breaks the client's automated deploy (`FASTAP_SSH_PASS`) |
| Deleting the 3 existing SSH keys | `fastap-codex-deploy`, `replit-deploy`, `github-actions-fingo` — breaks CI/CD |
| Editing Nginx config | A syntax error takes **all** sites offline |
| `apt upgrade` | Can break any of the 18 projects |
| `rm -rf` anything | Linux has no recycle bin |

## 🗄️ Database rules

- **Never** run `scripts/db-sync-critical.sql` or `scripts/migrate-production.sql`
  against live without a fresh snapshot first.
- **Never** run `UPDATE` or `DELETE` without a `WHERE` clause.
- Local dev DB runs on port **5433** (port 5432 is your other PostgreSQL — leave it alone).
- The only place the DB connection is configured is `.env` → `DATABASE_URL`.
  Apps and websites never talk to the database directly; only the API server does.

## 🤖 Never hand-edit generated code

These are regenerated by tooling. Your changes will silently disappear.

```
lib/api-zod/               ← generated from the OpenAPI spec
lib/api-client-react/      ← generated React Query hooks
kitchenapp/lib/data/generated/
artifacts/*/dist/          ← build output
```

Change the **source** (`lib/api-spec/`) and regenerate instead.

## ✅ Local setup (safe — nothing here touches live)

```powershell
cd "c:\Users\Admin\Desktop\FastMenuWeb&App\fastap-os"
```

Run this **first in every new terminal** — `.env` is not auto-loaded by this project:

```powershell
. .\load-env.ps1
```
*(the leading dot + space matters — it must be dot-sourced)*

**Terminal 1 — Database** *(leave running)*
```powershell
$env:PGPORT='5433'; node scripts/start-db.mjs
```

**Terminal 2 — API** → http://localhost:8080
```powershell
. .\load-env.ps1
$env:PORT='8080'
pnpm dev:api
```

**Terminal 3 — Web panels** → http://localhost:5000
```powershell
. .\load-env.ps1
pnpm dev:web
```

**Terminal 4 — Mobile app**
```powershell
pnpm dev:kitchenapp        # or dev:waiterapp / dev:housekeepingapp
```

> ⚠️ `pnpm db:init` is broken — it hangs forever. Use `db:start` and `db:setup` separately.

## 🧪 Before and after every change

```powershell
pnpm smoke:mobile           # the 3 mobile apps' API
pnpm smoke:all-panels       # the 3 web panels
pnpm typecheck              # TypeScript errors
cd kitchenapp; flutter analyze
```

Run them **before** you start (to know your baseline) and **after** you finish.
If something breaks, you'll know it was you — and you'll know immediately.

### One change can break three apps

`waiterapp` and `housekeepingapp` both depend on `kitchenapp`:

```yaml
dependencies:
  kitchenapp:
    path: ../kitchenapp
```

**Edit kitchenapp → test all three.**

Likewise, `fastap-admin` contains all three web panels (admin + restaurant + user).
**Change one → check all three.**
